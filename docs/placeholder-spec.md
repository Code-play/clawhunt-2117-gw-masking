# 占位符规范（S5-GW-010 交付物之 README）

本规范定义模型网关在「调用前脱敏」阶段产出的占位符、序号规则、映射表加密存储格式与还原规则。
凡是与网关交互的模块（网关编排、厂商适配、业务侧回显、审计与计费）都按本文实现。

## 1. 术语

| 术语 | 含义 |
| --- | --- |
| 原值 | 识别器命中的敏感值，例如手机号、证件号、邮箱；只允许存在于内存与加密映射表中 |
| 占位符 | 替换原值的 `[[TYPE_SEQ]]` 文本，例如 `[[PHONE_1]]` |
| 映射表 | 占位符 → 原值的对应关系；本单要求加密存储到 Redis |
| 命中数 | 一次请求中被替换的**出现次数**（同一值重复出现就重复计数） |
| 去重数 | 一次请求中不同原值的个数 |

## 2. 占位符语法

```text
[[TYPE_SEQ]]
```

- `[[` 与 `]]` 是固定定界符，中间是类型名、下划线、序号。
- `TYPE` 取自封闭集合 `PHONE` / `IDNO` / `EMAIL`（区分大小写）。
- `SEQ` 是从 `1` 开始、按**同类型**单独计数的十进制整数，上限 `9999`。
- 语法正则（网关与校验共用）：`\[\[(PHONE|IDNO|EMAIL)_(\d{1,4})\]\]`。

示例：`[[PHONE_1]]`、`[[PHONE_2]]`、`[[IDNO_1]]`、`[[EMAIL_1]]`。

## 3. 类型与识别规则

| 类型 | 识别规则 | 边界处理 |
| --- | --- | --- |
| `PHONE` | 中国大陆手机号 `1[3-9]\d{9}`，可带 `+86` / `86` 前缀，3-4-4 分组之间允许一个空格或连字符 | 前后不得是数字，避免把更长的数字串截成手机号 |
| `IDNO` | 18 位证件号：首位 `1-9`，随后 16 位数字，末位数字或 `X/x` | 前后不得是数字或 `X/x`；**不校验校验位**，形状命中即脱敏（隐私优先，见下） |
| `EMAIL` | 常规邮箱 `local@domain.tld`（本地部分允许 `._%+-`） | 先于手机号匹配，避免把邮箱本地部分里的数字当成手机号 |

识别优先级为 `EMAIL` → `IDNO` → `PHONE`，重叠区间只保留优先级更高的命中；对外暴露的
`Recognizer` 协议允许追加识别器（例如 NER、企业内部的 ID 名录），追加的识别器与内置规则一起做重叠排除。

`IDNO` **不**用校验位决定是否脱敏：虚构测试数据经常是形状正确、校验位错误的号码，若按校验位过滤就会漏脱敏。
需要「分类」时用 `app.masking.recognizers.is_valid_id_checksum`，不要用它决定要不要脱敏。

## 4. 序号分配

1. 分配器是**请求级**的：每次 `mask(messages, request_id)` 新建一个分配器。
2. 同一请求内，**相同类型 + 相同原值**永远复用同一占位符，不因出现在不同 message、不同 role 而改变。
3. 序号按**首次出现顺序**递增，且**每种类型独立计数**：先出现邮箱再出现手机号，得到 `[[EMAIL_1]]` 与 `[[PHONE_1]]`。
4. 新请求从 `1` 重新开始；`request_id` 不同即互不共享映射。
5. 同一原值重复出现会累加命中数，但不新增占位符。

示例（同一请求）：

```text
输入：手机 13812345678，再确认 13812345678，邮箱 zhang.san@example.com，证件 11010519491231002X
输出：手机 [[PHONE_1]]，再确认 [[PHONE_1]]，邮箱 [[EMAIL_1]]，证件 [[IDNO_1]]
masked_entity_count = 4（手机出现 2 次 + 邮箱 1 次 + 证件 1 次）
distinct_values = 3
```

## 5. system 消息固定说明

脱敏后，在**最后一条** `role == "system"` 的消息末尾追加（原文，逐字）：

```text
文中 [[类型_序号]] 为占位符，请原样保留，不要改写或推测
```

- 原 content 非空时以两个换行分隔；content 为空时只保留说明。
- 没有任何 system 消息时，在 messages 开头插入一条 `role=system`、content 为该说明的消息。
- content 是分片数组（`[{"type":"text","text":...}]`）时，说明作为新的 text 分片追加。
- 该说明不含任何原值，且其中的 `[[类型_序号]]` 是中文占位写法，不会与真实占位符冲突。

## 6. 命中数回填

- `x_gw.masked_entity_count`：本请求被替换的出现次数（含重复值），整数，无命中为 `0`。
- 网关把它同时放进响应体（`x_gw.masked_entity_count`）与响应头 `x-gw-masked-entity-count`，供计费与指标使用。
- 另有 `x_gw.masked`（布尔）标识本次是否真的做了脱敏；功能开关关闭时为 `false`。

## 7. 加密存储格式

| 项 | 规定 |
| --- | --- |
| 键 | `gw:mask:{request_id}`；`request_id` 需匹配 `[A-Za-z0-9][A-Za-z0-9._:-]{7,127}` |
| TTL | `600` 秒（`GW_MASK_TTL_SECONDS` 可配，验收以 600 为准） |
| 算法 | AES-256-GCM，12 字节随机 nonce |
| 明文 | 映射 JSON：`{"request_id":..., "placeholders":{token: value}, "sequences":{TYPE: n}, "distinct_values":n, "hits":n}` |
| 附加数据（AAD） | `gw:mask:{request_id}:v1`，把密文绑定到请求，跨请求重放会解密失败 |
| 值编码 | `base64url(version(1 byte, 0x01) ‖ nonce(12) ‖ ciphertext‖tag)` |
| 密钥 | 环境变量 `GW_MASK_KEY`：base64 编码的 32 字节，或长度 ≥16 的口令（HKDF-SHA256，salt `gw-mask-v1`，info `gw:mask:key`） |
| 失败关闭 | 密钥缺失/过短、密文被篡改、AAD 不匹配、Redis 不可用，一律报错而不是退回明文 |

因此，从 Redis 直接读到的值既看不到原值，也看不到映射表结构；只有持有 `GW_MASK_KEY` 的一方能解密。

## 8. 还原与生命周期

1. 厂商响应里可能带占位符（模型按要求原样保留），网关用同一 `request_id` 解密映射并替换回原值。
2. 还原成功后**立即删除** `gw:mask:{request_id}`；再次还原返回 `410`（映射不存在或已还原）。
3. 只替换映射表中存在的 token；映射里没有的 `[[TYPE_SEQ]]` 原样保留，避免误伤用户手写文本。
4. 厂商调用失败或网关中途异常时丢弃映射（不等 TTL），避免留下无人使用的可还原数据。
5. 功能开关关闭时走显式旁路：不改写 messages、不写映射、`masked_entity_count = 0`，并以 WARN 日志记录旁路事实（不含内容）。

## 9. 拒绝规则（快速失败）

| 情形 | 结果 |
| --- | --- |
| 输入文本已包含 `[[TYPE_SEQ]]` 形式 token | `422`，拒绝脱敏（网关 token 与用户 token 不可区分） |
| `request_id` 不合法 | `422` |
| messages 为空、role 缺失、content 形状不支持 | `422` |
| Redis 中没有该 `request_id` 的映射（过期/已还原） | `410` |

## 10. 审计与开关

- `mask_enabled` 默认开启；无显式配置行时按 `GW_MASK_ENABLED_DEFAULT`（默认 `true`）。
- 读取优先级：站点级行 > 组织级行 > 默认值。
- 修改必须由 `gateway_admin` 角色发起（`X-GW-Actor-Role: gateway_admin`），并写 `gw_audit_log`
  （`action = gw.feature_flag.updated`，`detail` 含 flag、前后值与原因）。其他角色返回 `403` 且不写审计。
- 审计明细只允许元数据：写入前会用同一套识别器检查，命中手机号/证件号/邮箱即拒绝写入。

## 11. 日志约束

- 允许记录：`request_id`、命中数、去重数、占位符类型、错误类别、耗时。
- 禁止记录：消息正文、原值、占位符对应的原值、映射表明文、密文内容。
- 错误信息不得回显输入内容（冲突错误只说明存在保留语法，不带 token 原文）。

## 12. 扩展新类型

新增类型（例如 `BANKCARD`）需要同步三处，且不涉及数据库迁移：

1. `app/masking/placeholders.py` 的 `TYPES` 与 `TOKEN_PATTERN` 白名单；
2. `app/masking/recognizers.py` 的识别规则与优先级；
3. 本文第 2、3 节，以及测试中的占位符断言。

因为占位符类型是封闭集合，旧版本网关遇到未知类型会原样保留该 token 而不是误还原，跨版本升级是安全的。
